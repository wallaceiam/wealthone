# Legacy iCloud recovery

Approved by user “so lets do that”, following the read-only recovery/preview/export proposal. Direct execution continues on the existing feature branch; preserve unrelated edits and current app identities.

The old React Native app used prefixed NSUbiquitousKeyValueStore strings. The current reader ignores synchronization failure, reads immediately and imports automatically only while the native event log is empty. Replace this with a notification-driven, read-only discovery session accessible from Home onboarding and Settings even after a new portfolio starts. Observe before requesting synchronization, inspect cached known keys, and continue observing delayed changes after a bounded waiting period. Timeout means no data received yet, never proof of deletion. Distinguish account unavailable, synchronize rejected, malformed values, quota notification, account change and simulator unsupported. Invalidate recovered previews on account changes; retries cancel old subscriptions/deadlines. Do not gate legacy KVS recovery on CloudKit account/container availability.

Scan all three logical keys in priority order (persist:wealthone_data, wealthone, backup), preserving distinct candidates so an older backup is not silently substituted. Decode/validate with existing legacy decoder, expose account/date-record/goal preview and candidate source. Export validated baseline JSON and a raw known-key original-data archive for recovery support. Do not read unrelated iCloud keys or log financial payloads. Never write/remove/synchronize values into the legacy store; synchronize requests downloads only because this reader never sets values.

Import is explicit, separately confirmed, and preserves the event log. Before replacement, write a full-history backup atomically; abort if backup fails. Revalidate candidate, preserve existing goal when recovered goal is empty (consistent with existing baseline imports), then append replacement epoch. Unavailable local storage follows existing restore flow rather than overwriting corrupt files.

Add an optional WealthOneRecovery scheme using original bundle ID ca.mymojo.wealthone and original KVS entitlement, same team, no CloudKit entitlement. It reuses discovery/preview/export UI without an import callback or native AppModel. No React Native runtime. This utility may reinstall under the old app identity; user reports old app is not installed. Do not auto-install on physical devices or register identifiers remotely. Native app retains its own bundle ID, CloudKit container and Watch identities.

Tests cover notification-before-sync races, delayed candidates, timeout with later delivery, account invalidation, failed synchronization, corrupt-current/valid-backup, archive round trips and backup-failure atomicity. Simulator never touches real KVS; validate discovery/session with fake source in unit tests and simulator UI limitations explicitly. Signed-device entitlement/account/download behavior remains user validation, not something local builds can certify.
